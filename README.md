> **Note on the data.** This file contains **723 exact duplicate rows among
> 1,025**, so there are only **302 distinct patients**. That fact is the subject
> of this study, not an error in the copy supplied here.

## How the paper's protocol was recovered

The paper does not state its train/test split. All three of its reported
accuracies are exact integer fractions of 205:

```
0.9268 = 190/205      0.9073 = 186/205      0.9853 = 202/205
```

205 = 20% of 1025, which gives a random 80:20 hold-out on the full file.
`part1_reproduce.py` implements exactly that.

## Key results

Reproduction, single 80:20 split, seed 42:

| Model | Paper | Reproduced |
|---|---|---|
| Decision Tree | 0.9268 | 0.9854 |
| Random Forest | 0.9268 | **1.0000** |
| XGBoost | 0.9073 | **1.0000** |
| Stacking | 0.9853 | **1.0000** |

Under the leakage-aware grouped protocol (25 folds):

| Model | Groups ignored | Grouped CV | Δ |
|---|---|---|---|
| Decision Tree | 0.9940 | 0.7521 | −0.2418 |
| Stacking (paper) | 0.9957 | 0.7915 | −0.2042 |
| **DPCS (proposed)** | 0.9945 | **0.8075** | −0.1870 |
| Naive Bayes | 0.8224 | 0.8081 | −0.0144 |
| Logistic Regression | 0.8455 | 0.8162 | −0.0292 |

98.54% of test rows have an exact duplicate in the training set under a random
80:20 split.
